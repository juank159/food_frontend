================================================================================
                     VIOLACIONES ARQUITECTURA (DRY)
================================================================================

🔧 CRÍTICAS:

1. CONTROLLERS DUPLICADOS (5 similar pattern):
   - CategoriesController
   - OrdersController
   - ProductsController
   - TableStatusController
   Todos usan el mismo patrón: loadData(), filterBy(), search(), clearFilters()
   SOLUCIÓN: Crear BasePaginatedController<T> genérico

2. FORM CONTROLLERS DUPLICADOS (3):
   - CategoryFormController
   - ProductFormController
   - OrderFormController
   Patrón idéntico: validación, guardado, refresh, navegación
   SOLUCIÓN: Crear BaseFormController<T> abstracto

3. DIALOGS DUPLICADOS:
   - ProcessPaymentDialog
   - ReserveTableDialog
   - OccupyTableDialog
   Patrón similar de confirmación
   SOLUCIÓN: Crear BaseConfirmationDialog<T>

4. ERROR HANDLING:
   - Código repetido en todos los repositorios
   - TableStatusRepository repite try-catch
   SOLUCIÓN: Crear RepositoryErrorHandler mixin

5. BINDINGS:
   - Todas siguen el mismo patrón
   - Mejora: inyectar use cases directamente
   SOLUCIÓN: Mejorar bindings para testing
